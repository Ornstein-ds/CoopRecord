# CoopRecord

Версия ветки **dev: v4.2.1** (предварительный релиз).

В v4.2.1 добавлена расшифровка разговора. Для совместной работы всем участникам нужна эта сборка: протокол расшифровки **8** несовместим со стабильной v4.1.1. Скачать: [предварительный релиз v4.2.1](https://github.com/Ornstein-ds/CoopRecord/releases/tag/v4.2.1). Стабильный канал автообновления предварительные релизы не устанавливает.

Приложение для совместной записи подкаста на **Windows 10/11 x64**: **встроенная голосовая связь и персональный микшер**, синхронные микрофонные дорожки и **общий саундпад 3×3 с горячими клавишами**. Один хост и до семи участников. Записи сохраняются только у хоста; звуки саундпада автоматически копируются во временные папки участников. Go, C-компилятор и установка приложения для запуска готового EXE не нужны.

## Оформление

Интерфейс поддерживает светлую и тёмную темы: переключатель находится справа вверху, кнопка **«Как в Windows»** возвращает автоматический выбор по настройкам системы. Выбор сохраняется и применяется без перезапуска, включая микшер и саундпад. Кнопки, поля и индикаторы оформлены со скруглениями. На Windows 11 22H2 и новее верхняя панель использует системный Acrylic; при недоступности эффекта или включённом режиме высокой контрастности применяется непрозрачный фон. Настройки записи и формат WAV от оформления не зависят.

## Локальная расшифровка разговора

Справа добавлена прокручиваемая история реплик; окно расширено на 15%. Текст появляется после паузы в речи и обработки моделью. Когда читаете старые реплики, новые сообщения не сбрасывают прокрутку. Имена берутся из отдельных микрофонных дорожек: одновременная речь участников обрабатывается отдельно. Звук компьютера и саундпад не расшифровываются.

**Модель нужна только хосту.** Участникам передаётся готовый текст. Для работы после установки интернет не требуется; аудио не отправляется в облачные сервисы. Во время разговора вне записи гости дополнительно передают микрофон хосту по TCP (около 1,1 Мбит/с на гостя); во время записи распознавание использует уже передаваемые блоки. Вне записи история хранится в памяти до следующей сессии.

Установка на ПК хоста, один раз, из папки приложения:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-transcription.ps1
```

При запуске скрипта из исходников файлы попадут в `dist\stt`; из готовой сборки — в `stt` рядом с EXE. Скрипт скачивает около 612 МБ, проверяет SHA256 и устанавливает:

- [Whisper large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo), мультиязычную открытую модель, в [формате GGML Q5_0](https://huggingface.co/ggerganov/whisper.cpp/tree/main). Файл весов — 574 МБ, лицензия MIT. Язык задан `ru`, режим — распознавание, без перевода на английский.
- `whisper-server.exe`: [сборку whisper.cpp с Vulkan](https://github.com/jiang1997/whisper.cpp-release/releases/tag/v1.8.4.1), подготовленную сообществом, с опубликованным рецептом сборки. Это не официальный бинарный релиз OpenAI. Сервер запускается скрыто, слушает только `127.0.0.1` на случайном порту и завершается при отключении хоста. Для работы нужны актуальные драйверы GPU с Vulkan.

Перед созданием сессии выберите **GPU · Vulkan**, **CPU** или **Выключена**. Кнопка **«Выбрать модель…»** принимает другие локальные мультиязычные Whisper-модели в GGML `.bin`; GGUF, PyTorch и модели `.en` для этой задачи не подходят. Движок должен лежать в `stt` рядом с EXE либо рядом с выбранной моделью. На ПК участника устанавливать модель и движок не нужно. Модели не входят в обычный ZIP приложения и не перекачиваются при его обновлении.

Проверено на Radeon RX 570 8 ГБ / Ryzen 5 5600: large-v3-turbo Q5 работает через Vulkan. После тестового распознавания процесс занимал около **0,86 ГиБ выделенной видеопамяти**, веса полностью размещены на GPU. Русский пример длительностью 7,08 секунды обработан примерно за 2,15 секунды. Это замер одного фрагмента, а не гарантия скорости для любой речи и числа участников; потребление памяти других приложений сюда не входит. CPU-режим медленнее.

Во время записи в её папке постепенно сохраняется **`transcript.md`**. При остановке приложение дописывает последние реплики и упорядочивает строки по времени. Каждая строка начинается с времени от начала WAV и имени:

```markdown
[00:00:12.340] **Влад:** Давай вернёмся к предыдущей теме.
[00:00:16.080] **Друг:** Мы обсуждали первый выпуск.
```

Используется синхронизация монотонных часов хоста и участников и та же поправка микрофона, что у WAV; часовые пояса не влияют на отсчёт. В Markdown входят только реплики данной записи, разговор до начала и после остановки остаётся в окне. Тайминг начала фразы оценивает модель, поэтому точность распознавания и границ фраз не абсолютна. Длинная непрерывная речь делится на фрагменты до 12 секунд. При отставании видна очередь; переполнение или ошибка модели отмечается как неполная расшифровка, запись WAV продолжается. Исходные WAV можно расшифровать повторно внешним инструментом; кнопка восстановления WAV не пересоздаёт текст.

## Скачать и запустить

Скачайте `CoopRecord-windows-x64.zip` из [Releases](https://github.com/Ornstein-ds/CoopRecord/releases), распакуйте и запустите `CoopRecord.exe` на обоих компьютерах. Сборки каждого коммита также доступны в [Actions](https://github.com/Ornstein-ds/CoopRecord/actions).

1. Войдите в одну сеть RadminVPN и подключите наушники. **С v3.0.1 отдельный звонок не нужен:** голосовая связь автоматически работает между всеми подключёнными участниками, включая хоста.
2. Каждый вводит своё имя, **выбирает микрофон** и нажимает **«Проверить звук»**. Индикатор показывает уровень; тест ничего не сохраняет. Выбор устройства запоминается. Кнопка «Обновить» перечитывает подключённые микрофоны.
3. Хост выбирает роль **«Хост»**, папку сохранения и нажимает **«Создать сессию»**. Адрес `0.0.0.0:47652` означает прослушивание всех сетевых интерфейсов. Можно указать собственный IP RadminVPN, чтобы принимать соединения только через него.
4. Хост передаёт другу свой **IP из RadminVPN**, порт `47652` и ключ сессии из окна приложения. Адрес `0.0.0.0` передавать другу не нужно.
5. Участник выбирает роль **«Участник»**, вводит адрес хоста, например `26.12.34.56:47652`, и тот же ключ. Нажимает **«Подключиться»**.
6. Когда у хоста напротив всех участников указано **«готов»**, он нажимает **«Начать запись»**. После секундной подготовки начинается общая временная шкала.
7. Хост нажимает **«Стоп»** и дожидается сообщения «Сохранено». Кнопка **«Открыть папку»** открывает текущую запись. Следующее нажатие «Начать запись» создаёт новую папку.

Во всех полях ввода работают **Ctrl+A** (выделить всё) и **Ctrl+Backspace** (удалить предыдущее слово или выделенный текст). При ошибке подключения IP и ключ остаются в полях. При переключении роли сохраняется отдельный набор этих значений для хоста и участника до закрытия приложения.

## Микшер и звук компьютера

- Высота макета окна увеличена на 50%; внизу появился микшер. На небольших экранах окно автоматически уменьшается, чтобы целиком помещаться.
- Первый фейдер управляет всем саундпадом, второй — **звуком вашего компьютера**, остальные — отдельными собеседниками, включая хоста. Свой микрофон обратно не воспроизводится, его индикатор остаётся в блоке «Ваш звук».
- Под вторым фейдером находится кнопка **«Мьют включён»**. Нажмите её в подключённой сессии, чтобы передавать звук других приложений всем участникам. Повторное нажатие останавливает захват и передачу. При каждом подключении мьют включён; его выключение не сохраняется между сессиями. Звук самого CoopRecord исключён из захвата, поэтому разговор и саундпад не отправляются повторно. Для этой функции нужна **Windows 11**; при недоступности захват останется выключенным.
- По умолчанию фейдер стоит на **65% высоты** и даёт **100% исходной громкости**. Слева — шкала с широкой жирной отметкой этого уровня. Ниже громкость уменьшается до нуля, выше — усиливается до **200%**. Регуляторы работают во время воспроизведения и записи; поддерживаются мышь и клавиатура (Tab, стрелки, Home/End). Усиление уже громкого сигнала может вызвать искажения при достижении цифрового предела.
- Рядом с каждым фейдером расположен вертикальный индикатор пикового **входного уровня**, до регулировки громкости. Поэтому видно, что собеседник говорит, даже когда его громкость выставлена в ноль.
- Участники появляются и исчезают автоматически. Одинаковые имена не объединяют их каналы. При уходе другого человека настройки оставшихся сохраняются; новое подключение начинает со 100%. Громкость саундпада сохраняется до закрытия приложения.
- Фейдер **«Звук компьютера»** меняет громкость, передаваемую собеседникам и сохраняемую в отдельный `desktop-NN.wav` и общий `mix.wav`. Во время мьюта на этой дорожке тишина. Остальные фейдеры меняют только **ваше прослушивание**: громкость саундпада и суммарного входящего звука каждого собеседника (микрофон и компьютер). Они не меняют записываемые дорожки.

Для сессии используйте одну и ту же сборку на всех ПК. В опубликованной v4.1.1 используется протокол 7; в текущей сборке с расшифровкой — протокол 8. Восстановление старых WAV-сессий поддерживается.

## Голосовая связь

- Микрофон, выбранный в приложении, передаётся остальным с момента подключения до отключения от сессии. Кнопки начала и остановки записи управляют сохранением файлов и не выключают разговор. До начала записи голос на диск не сохраняется.
- Каждый слышит остальных, включая участников на других ПК; собственный микрофон приложение обратно не воспроизводит. Хост пересылает голос участникам, поэтому дополнительные соединения между гостями настраивать не нужно.
- Вывод идёт через **устройство воспроизведения Windows по умолчанию**, выбранное при подключении. Чтобы сменить его, выберите другое устройство в Windows и переподключитесь. Используйте наушники: автоматического подавления акустического эха нет, звук из колонок может повторно попасть в микрофон.
- Для голоса используется **UDP на том же номере порта**, что и TCP-сессия: по умолчанию `47652`. Разрешите CoopRecord в брандмауэре для VPN-сети; если правила задаются вручную, нужны TCP и UDP. Состояние приёма голоса показано справа под саундпадом. Если запись подключается, но голоса нет, проверьте UDP и устройство вывода.
- Небольшой буфер сглаживает сетевые задержки; плавная подстройка скорости компенсирует дрейф часов микрофона и устройства вывода. Потери UDP могут быть слышны в разговоре, но исходные дорожки записи передаются отдельно по TCP. Загрузка саундпада и операции с диском не блокируют голосовой поток внутри приложения.
- Голос передаётся без сжатия: PCM 48 кГц / 16 бит / моно, около **1 Мбит/с на один голосовой поток** с запасом на VPN. При `N` участниках, включая хоста, каждому гостю нужен входящий канал примерно `N−1` Мбит/с и исходящий 1 Мбит/с; хосту — входящий `N−1` и исходящий `(N−1)²` Мбит/с. Во время записи добавляется около 1,1 Мбит/с от каждого гостя к хосту. Для двух ПК ориентируйтесь на 2 Мбит/с в обе стороны с запасом.

Если Windows запросит сетевой доступ, разрешите приложению входящие соединения для используемой VPN-сети. Приложение использует **TCP 47652**; порт можно изменить в поле адреса. Системные настройки безопасности приложение не меняет.

## Обновление приложения

Начиная с **v1.0.1**, в верхней части окна отображается установленная версия и есть кнопка **«Обновить приложение»**. Вне сессии она проверяет последний стабильный GitHub Release и, если он новее, скачивает `CoopRecord-windows-x64.zip` в `%LOCALAPPDATA%\CoopRecord\Updates\vX.Y.Z`. Токен и вход в GitHub не нужны. Версия, которая уже установлена или старее установленной, повторно не скачивается.

После проверки размера и SHA-256 приложение покажет сообщение и откроет папку с архивом. Закройте CoopRecord, распакуйте ZIP и замените файлы программы. Записи и настройки сохранятся. При ошибке загрузки неполный файл удаляется; текущий EXE не меняется. Для перехода с v1.0.0 нужно один раз скачать новый ZIP вручную из Releases.

## Саундпад — v2.0.3

Слева запись, справа девять квадратных кнопок в сетке 3×3. В v2.0.3 стороны кнопок уменьшены на 35%: с 148 до 96 пикселей. На небольшом экране окно уменьшается, чтобы поместиться целиком.

1. **Хост до создания сессии** назначает звуки кнопками **«Файл…»** рядом с падами. «Убрать» очищает слот; оставлять часть кнопок пустыми можно. Пути запоминаются. Для изменения набора после подключения нужно завершить сессию и создать её заново.
2. Поддерживаются **MP3** и **WAV PCM 8/16/24/32 бит и float32** (WAV: моно/стерео, 8–192 кГц), до **2 минут** на звук и до 64 МБ на исходный файл. Хост автоматически приводит звуки к PCM 48 кГц / 16 бит / моно перед передачей участникам. Для MP3 не нужны внешние конвертеры и кодеки; итоговая запись по-прежнему сохраняется в WAV.
3. После подключения хост автоматически передаёт звуки каждому участнику блоками. Участник сохраняет их в `%TEMP%\CoopRecord-sounds-*` и проверяет размер и SHA-256. Внизу саундпада показан прогресс; у хоста также перечислены проценты каждого участника. Общий индикатор хоста показывает готовность самого отстающего ПК. **Начать запись нельзя, пока все звуки не проверены на всех ПК и часы не синхронизированы.**
4. Нажатие на пад или его горячую клавишу на любом ПК отправляет запрос хосту. **В сессии звучит один пад:** повторное нажатие останавливает его и сбрасывает позицию; нажатие другого останавливает текущий и запускает выбранный с начала. Хост назначает общее время команды и рассылает его всем, включая инициатора. Поэтому запуск, остановка и замена происходят с небольшой задержкой на синхронизацию. Каждый компьютер воспроизводит свою локальную копию через устройство вывода Windows по умолчанию. Быстрые нажатия обрабатываются по порядку, в том числе до начала уже запланированного звука. Перед началом новой записи дождитесь окончания звука или остановите его повторным нажатием.
5. По умолчанию горячие клавиши — **Ctrl+Alt+1…9**. Нажмите поле под падом, введите нужное сочетание и нажмите **«Применить горячие клавиши»**. Настройки локальные: каждый участник выбирает свои. Требуется Ctrl или Alt; сочетания должны быть уникальными и свободными в Windows. Клавиши работают и при свёрнутом окне. Пустое поле отключает сочетание; при закрытии программы регистрации освобождаются.

Запуск имеет запас минимум **500 мс** для доставки команды; при большом RTT запас увеличивается. Используются монотонные часы, часовые пояса не влияют на запуск. Точность слышимого старта зависит также от планировщика Windows и задержки устройства вывода; это не аппаратная синхронизация до сэмпла. Опоздавшая команда пропускает уже прошедшую часть звука, сохраняя общую временную позицию.

В записи с настроенным саундпадом создаётся отдельный **`soundpad.wav`**, а его звук добавляется в **`mix.wav`**. Остановки и переключения обрезают звук в обоих файлах в назначенный момент, в том числе при восстановлении записи. Микрофонные WAV остаются отдельными. Голоса в миксе усредняются как раньше, затем добавляется саундпад; сумма ограничивается диапазоном PCM. Используйте наушники, чтобы проигрываемые звуки не попали в микрофон повторно.

В папке записи сохраняются копии `pad-01.pcm`…`pad-09.pcm` и журнал `soundpad.jsonl`, необходимые для восстановления саундпада. Временный кэш сессии удаляется при отключении; после аварийного завершения оставшиеся папки `%TEMP%\CoopRecord-sounds-*` можно удалить вручную. Самостоятельные копии в папке записи сохраняются.

Новая версия восстанавливает старые записи, сохраняя наложения звуков из v2.0.1–v2.0.2. Записи с остановками и переключениями саундпада восстанавливайте в v2.0.3 или новее.

## Результат

Каждая запись находится в отдельной папке, например `2026-10-06_17-30-00_123456789`:

```text
track-00.wav       — только микрофон хоста
track-01.wav       — только микрофон первого участника
track-02.wav       — следующий участник, если он был
desktop-00.wav     — звук компьютера хоста
desktop-01.wav     — звук компьютера первого участника (далее по тому же номеру)
mix.wav            — общий синхронизированный монофонический микс
soundpad.wav       — звуки саундпада (если хост назначил звуки)
soundpad.jsonl     — журнал синхронных запусков саундпада
pad-01.pcm        — копия первого звука для восстановления; до pad-09.pcm
session.json       — имена участников, соответствие файлов, поправки, предупреждения
track-00.capture   — исходные аудиоблоки для восстановления
track-00.clock     — метки синхронизации; у хоста пустой файл
...
```

WAV: **PCM, 48 000 Гц, 16 бит, моно**. Все итоговые дорожки имеют одинаковую длину и общий ноль, их можно импортировать в редактор с одной позиции. В `mix.wav` голоса усредняются по числу участников, затем добавляются звук компьютеров и саундпад с ограничением суммы до диапазона PCM. Для монтажа и собственной обработки используйте отдельные дорожки. Файлы `desktop-NN.wav` создаются для каждого участника, даже если захват всё время был выключен; в этом случае они содержат тишину.

Во время записи хост непрерывно пишет исходные блоки, синхронизированные WAV создаются при остановке. Исходники сохраняются после экспорта; удалять их можно вручную после проверки готовых WAV. На час записи двух человек с захватом компьютера у обоих планируйте около **3,2 ГБ** без саундпада. Каждая активная дорожка записи требует примерно **1,1 Мбит/с дополнительно к голосовой связи** от гостя к хосту. В файлы микрофона не подмешивается воспроизводимый голос собеседников. Для восстановления сохраняются также `desktop-NN.capture` и `desktop-NN.clock`.

## Синхронизация

Часовые пояса и показания настенных часов не участвуют в синхронизации. WASAPI сообщает QPC-метку первого сэмпла каждого блока. Протокол обменивается четырьмя монотонными метками, оценивает разницу счётчиков ПК и измеряет RTT. Сверка продолжается во время записи. Экспорт выбирает замеры с минимальным RTT и интерполирует дрейф часов. Частота аудиоустройства оценивается по всему непрерывному участку записи; пересчёт сэмплов сохраняет непрерывность звука на стыках блоков. Мелкие колебания временных меток не превращаются в паузы или обрезанные фрагменты.

Так задержка доставки TCP-пакета не становится сдвигом дорожки. Абсолютная точность всё же зависит от асимметрии сетевых задержек и меток драйвера; это не аппаратная синхронизация с гарантией до сэмпла. Проверяйте результат короткой пробной записью перед длинным выпуском.

Поле **«Поправка, мс»** с диапазоном −2000…2000 задаёт постоянный сдвиг вашего микрофона. Обычно оставляйте `0`. Положительное значение сдвигает голос **позже**, отрицательное — **раньше**. Поправка применяется к отдельному WAV и миксу. Можно изменить `CorrectionMS` нужной дорожки в `session.json` после остановки и заново выполнить восстановление из сохранённых исходников.

## Обрыв связи и восстановление

Начиная с **v1.0.2**, краткий разрыв потока микрофона не останавливает сессию. Приложение сохраняет отметку драйвера, продолжает запись и оставляет тишину на месте пропуска, сохраняя положение последующего звука. Количество разрывов указывается после экспорта в предупреждениях и `session.json`. Обычный шум временных меток не считается разрывом. Чтение микрофона не ждёт записи и сброса файлов на диск.

В v1.0.2 для передачи отметок разрыва был введён протокол версии 2, в v2.0.1–v2.0.2 — версия 3 с саундпадом, в v2.0.3 — версия 4 с общими остановками и переключениями, в v3.0.1 — версия 5 с голосовой связью, в v4.0.1 — версия 6 со списком каналов микшера. Захват звука компьютера использует протокол 7 и формат сессии 5. Все участники должны использовать совместимые версии приложения. Новая версия читает старые записи.

При отключении участника, отказе микрофона, недостоверной временной метке, переполнении очереди или ошибке диска запись останавливается с предупреждением. Полученный хостом звук сохраняется; недостающие участки итогового файла заполняются тишиной. Аудио, которое не успело дойти до хоста, восстановить нельзя: локальных резервных файлов у участника нет.

После аварийного завершения приложения или ПК запустите CoopRecord, нажмите **«Восстановить WAV…»** и выберите папку с `session.json` и файлами `.capture` / `.clock`. Неполный последний блок отбрасывается с предупреждением; исходники не перезаписываются. Завершённые файлы WAV публикуются после успешного закрытия временного файла. Сбой питания может потерять последние данные, ещё не сохранённые ОС или накопителем.

Восстановление доступно также из командной строки:

```powershell
Start-Process .\CoopRecord.exe -ArgumentList '--recover', '"C:\Podcasts\session-folder"' -Wait
```

Восстанавливайте только завершённую запись. После обрыва отключитесь, подключитесь заново и начните новую запись. Подключение новых участников во время записи не разрешено. Максимальная длительность одной записи — **6 часов**, затем создайте новую: это оставляет запас до ограничения 4 ГБ на один WAV RIFF.

Ключ ограничивает доступ к сессии, а для голосовых UDP-пакетов выдаётся случайный токен каждому подключению. Приложение не добавляет собственное шифрование: используйте доверенную VPN-сеть, не открывайте порты в публичный интернет. В одной сессии хостом остаётся компьютер, создавший TCP-сервер; назначить второго хоста внутри неё нельзя. Отдельные независимые сессии могут существовать одновременно.

## Сборка из исходников

Нужен Go 1.24 или новее; проверено с **Go 1.27.1**. Исходники — Go, интерфейс — Win32, захват — WASAPI через `go-wca`. **CGO отключён**, C/C++ toolchain не нужен.

```powershell
git clone https://github.com/Ornstein-ds/CoopRecord.git
cd CoopRecord
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

`setup.ps1` устанавливает официальный Go SDK в `.tools/go`, сверяя SHA-256. Права администратора и изменение глобального PATH не нужны. Если Go уже установлен, `build.ps1` умеет использовать его из PATH. Git устанавливается отдельно с [git-scm.com](https://git-scm.com/downloads/win), если его ещё нет.

Результат: `dist/CoopRecord.exe`, ZIP для друга и контрольная сумма `dist/SHA256SUMS.txt`. `build.ps1` сначала запускает тесты и `go vet`, затем собирает EXE. Перед повторной сборкой закройте приложение.

```powershell
# Дополнительно проверить реальный микрофон: по 1 секунде на устройство,
# без сохранения или передачи звука. Нужны разрешения Windows.
powershell -ExecutionPolicy Bypass -File .\build.ps1 -TestAudio
```

Автотесты проверяют синхронизацию с разницей счётчиков в 13 часов, дрейф аудио и часов, непрерывный звук при шуме временных меток, интерполяцию на стыках блоков, сохранение настоящих разрывов, WAV-заголовки, микс, повреждённый хвост записи, повторные сессии, отключение участника, неверный ключ и ограничения сетевых сообщений. Проверка на двух физических ПК через RadminVPN остаётся обязательной перед первым настоящим выпуском.

Настройки интерфейса хранятся в `%APPDATA%\CoopRecord\settings.json`. Ключ сессии не сохраняется. Лицензии сторонних компонентов находятся в `THIRD_PARTY_NOTICES.txt`.

Технические источники: [WASAPI GetBuffer и QPC-метки](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer), [go-wca](https://github.com/moutend/go-wca), [официальные загрузки Go](https://go.dev/dl/).
